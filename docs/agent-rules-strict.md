# Agent Rules - Strict Drift Prevention Standard

Purpose: define non-negotiable operating rules that prevent agent drift in planning, implementation, review, and Jira closure.

Scope: all human+agent ticket work in this repository.

| Rule ID | Rule (Must) | Drift Risk Prevented | Enforcement Check | Required Evidence | If Violated |
|---|---|---|---|---|---|
| AR-01 | Read canonical docs before implementation: `docs/project-status.md`, `docs/architecture.md`, `docs/data-contracts.md`, and `docs/vat-rules.md` when VAT logic is in scope. | Working from stale or invented context. | Session start checklist includes all docs. | Session notes or prompt snippet listing loaded docs. | Stop work, reload docs, restart task framing. |
| AR-02 | Do not start coding unless ticket brief includes purpose, MVP usage, functional scope, security requirements, and acceptance criteria. | Ambiguous implementation and scope creep. | Validate brief completeness before first code change. | Ticket text or local brief file with all fields present. | Pause implementation and request missing requirements. |
| AR-03 | One ticket equals one feature branch. | Cross-ticket contamination and hidden drift. | Branch name maps to exactly one Jira issue. | `git branch --show-current` and ticket key alignment. | Split work immediately; move unrelated changes out. |
| AR-04 | Agent edits must stay inside assigned module paths. | Scope drift into other modules. | Diff path review before commit. | `git diff --name-only` contains only allowed paths. | Reject output; re-prompt with hard path bounds. |
| AR-05 | Changes to `/src/shared/**` require explicit team sign-off before implementation. | Shared-contract breakage across modules. | Confirm sign-off exists before touching shared files. | Link to decision note or explicit approval comment. | Revert shared edits from branch and escalate. |
| AR-06 | Data contract fields and types are immutable unless docs are updated first by team decision. | Field/type drift and integration breakage. | Compare generated fields against `docs/data-contracts.md`. | Review note confirming exact field/type match. | Block merge; update docs first or correct code. |
| AR-07 | VAT logic must match documented rules only; no guessed defaults, inferred exemptions, or undocumented rate handling. | Tax-rule drift and compliance defects. | Map each VAT branch/rate to `docs/vat-rules.md`. | Reviewer mapping notes in PR/review output. | Remove undocumented logic; request rule clarification. |
| AR-08 | Do not introduce new dependencies without team approval. | Dependency drift, security and maintenance risk. | Dependency diff check each PR. | No unapproved changes in dependency manifests. | Remove dependency or obtain approval first. |
| AR-09 | No "while I was at it" expansions: implement only requested scope. | Feature drift and hidden behavior changes. | Compare deliverable to explicit ticket scope. | Scope check line in review output. | Remove extras; keep only ticket-scoped changes. |
| AR-10 | Do not refactor unrelated code during feature delivery unless ticket explicitly includes refactor scope. | Behavioral regressions masked as cleanup. | Diff review for unrelated edits. | Review note: unrelated edits = none. | Split into separate ticket/branch or discard. |
| AR-11 | Agents must ask for clarification on uncertainty; assumptions are forbidden for contracts, VAT logic, security, or file ownership. | Confident guessing and silent drift. | Detect unresolved unknowns before coding. | Captured clarification question and answer. | Pause task until clarified. |
| AR-12 | Run reviewer gate with explicit first-line verdict `PASS` or `FAIL` before closure decisions. | Inconsistent quality threshold. | Review output parser verifies verdict line. | Saved review artifact file. | Ticket cannot advance to Done. |
| AR-13 | `Done` is allowed only after reviewer `PASS`; `FAIL` keeps ticket active (`In Progress` or `In Review`). | Premature closure and unresolved defects. | Jira transition is gated by verdict. | Jira plan/comment includes verdict evidence. | Reopen or move back and create fix loop. |
| AR-14 | Jira updates must be batched at end of session (status, assignee, comments together). | Workflow drift and partial state updates. | Use batch plan file and batch updater script. | Plan JSON plus updater execution log. | Re-run Jira updates using batch process. |
| AR-16 | Tests must cover changed critical behavior before review gate. | Undetected regressions and false PASS. | Run relevant unit/integration tests for changed paths. | Test run output attached or summarized. | Add tests/fixes before rerunning review. |
| AR-17 | Update tracking artifacts in same final change set: `CHANGELOG.md` and `docs/project-status.md` when applicable. | Documentation drift from shipped behavior. | Final pre-PR checklist includes both files. | Diff includes required doc updates. | Update docs before PR/merge. |
| AR-19 | Autonomous loops must have bounded retries and hard stop conditions on repeated FAIL or blockers. | Infinite churn and quality collapse. | Verify retry cap and stop conditions in automation scripts. | Script config/log shows capped retries. | Halt automation and switch to manual triage. |
| AR-20 | Closure report must capture changed files, reviewer output, and final Jira status. | Loss of auditability and weak handoff. | Generate end-of-ticket report artifact. | `finished-tickets/<ISSUE>.md` present and complete. | Regenerate report before closure. |
| AR-21 | Treat Markdown as authoritative, but retrieve context by topic/section, not by pasting entire documents each turn. | Token bloat and context dilution. | Prompt contains only relevant doc sections for current task. | Session prompt references specific headings/files. | Re-run with scoped retrieval only. |
| AR-22 | Documentation must be modular: split large docs into focused topic files when practical (for example auth, error contracts, VAT exceptions, API behavior). | Over-fetching large documents and noisy context. | New/updated docs follow topic-based structure. | PR diff shows modular doc files instead of monolith growth. | Refactor docs into topic files before relying on them in prompts. |
| AR-23 | Each canonical doc must include a compact rules summary at the top (5-10 bullets) used as first-pass retrieval. | Repeated full-document reads for routine checks. | Reviewer confirms summary block exists and is current. | Top-of-file summary block present in canonical docs. | Add/update summary block before task closure. |
| AR-24 | Use two-step retrieval: load summary first, then pull full sections only when a summary bullet is insufficient. | Unnecessary token spend from full-doc loading. | Session trace shows summary-first pattern. | Prompt snippets show summary load followed by targeted section load. | Restart task context with two-step retrieval. |
| AR-25 | Keep a compact global policy prompt for universal rules; keep detailed rules retrievable on demand. | Repeating long standards in every turn. | Shared system/session prompt size remains minimal and stable. | Presence of short policy file referenced by prompts. | Move verbose repeated text to retrievable docs. |
| AR-26 | MCP/session context must cache already retrieved sections per ticket/session and avoid reloading unchanged text. | Duplicate token usage across iterative turns. | Repeated turns reference cached section IDs/headers. | Session notes indicate cache hits or reused excerpts. | Enable cache discipline and continue from cached context. |
| AR-27 | Agent outputs must reference doc section titles/paths instead of restating large documentation blocks unless explicitly requested. | Response verbosity and duplicated context. | Review output checks for section references over doc restatement. | Output includes file+heading references for decisions. | Rewrite response to references-only style. |
| AR-28 | When documentation changes, update only impacted sections and summaries; do not republish unrelated content. | Churn and accidental drift in stable docs. | Doc diff limited to relevant headings. | PR doc diff scoped to impacted sections only. | Revert unrelated doc changes and re-submit focused update. |
